# 설계

무엇을 만드는지를 적는 문서다. 지금 유효한 결정만 담는다.

- 어떤 순서로 만드는지: `docs/implement-plan.md`
- 시안 캔버스: https://claude.ai/artifact/SS9pcbuwrXtQiJZUedUvug (비공개, 390px 폭 기준)

## 1. 개요

| 테마 | 주소 | 시안 | 대상 |
| --- | --- | --- | --- |
| 일반 테마 | `/` | 샘플 시안 S-01~S-09 | 모든 하객. 실물 청첩장의 QR 코드가 이 주소를 가리킨다. |
| 개발자 테마 | `/dev` | D-2 코드 에디터 | 동료 개발자. 링크를 따로 공유한다. |

하객이 이 페이지에서 끝내려는 일은 네 가지다.

1. 언제 어디서 하는지 확인하기
2. 찾아가는 길 확인하기
3. 축의금 계좌 복사하기
4. 축하 메시지 남기기

## 2. 공통 결정

- 문구(모시는 글, 혼주, 일시, 장소, 교통 안내)는 실물 청첩장의 것을 그대로 쓴다. 새로 쓰거나 늘리지 않는다.
- 사용자가 준 사진은 원본의 비율과 사각형 모양을 그대로 쓴다. 자르거나 모서리를 둥글리지 않는다.
- 영상과 배경음악은 넣지 않는다.
- 하객은 주로 QR 코드로 들어온다. 검색 엔진에는 노출하지 않는다. 예식이 끝나면 서비스를 내린다.
- 두 테마는 내용(`wedding.ts`), 로직, 방명록 DB를 공유하고 모양만 다르다.

## 3. 일반 테마의 기초

### 색상 토큰 (`src/app/globals.css`의 `@theme`)

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| `--color-background` | `#F8F5EF` | 모든 섹션의 배경. 240px 반복 질감 `public/images/paper-grain.png`를 함께 깐다. |
| `--color-card` | `#FFFFFF` | 카드, 버튼, 입력창, 시트의 면 |
| `--color-foreground` | `#1B1C1F` | 제목, 보조 버튼과 입력창의 테두리 |
| `--color-body` | `#3C3D40` | 본문, 토스트의 면 |
| `--color-muted` | `#6E6F73` | 보조 설명, 입력창 안내 문구 |
| `--color-line` | `#D9D3C7` | 카드 테두리, 구분선 |
| `--color-tile` | `#EDE8DE` | 사진을 불러오기 전의 자리 |
| `--color-primary` | `#4154FF` | 영문 머리말, 기본 버튼, 교통 안내 항목명, 예식일 하트, 지도 핀 |
| `--color-heart` | `#F772A1` | 카운트다운 문구의 하트 |
| `--color-danger` | `#E5000F` | 입력 오류 문구 |

- 흰 글자는 `--color-primary`와 `--color-body` 면 위에만 올린다.

### 서체 (`next/font/google`)

| 역할 | 서체 | 쓰는 곳 |
| --- | --- | --- |
| `font-sans` | 고운돋움 400 | 본문과 제목 |
| `font-serif` | Bona Nova 400 | 영문 머리말, 날짜와 숫자 |
| `font-strong` | Noto Sans KR 700 | 이름, 예금주 같은 굵은 글자 |

- 고운돋움에는 굵은 굵기가 없다. `font-weight: 700`을 직접 주지 않는다.

### 모양 규칙

- 섹션 머리말: 가운데 정렬. 블루 영문 머리말(13px, 자간 5px) 아래에 22px 한글 제목.
- 섹션 구분: 위 88px, 아래 80px 여백. 섹션 안의 구분은 1px 세로선.
- 카드: 흰 면, `--color-line` 1px 테두리, 반경 16px.
- 기본 버튼: `--color-primary` 면에 흰 글자, 높이 52px, 완전히 둥근 모서리.
- 보조 버튼: 흰 면에 `--color-foreground` 1px 테두리, 높이 48px, 완전히 둥근 모서리.
- 사각 버튼(지도 앱 링크, 공유): 흰 면, `--color-line` 1px 테두리, 반경 12px, 높이 52px.
- 터치 영역은 최소 44px. 문단에는 `word-break: keep-all`.
- 본문 컨테이너는 최대 448px이며 360px 폭에서도 넘치지 않는다.

### S-01 첫 화면

- 위에서부터: 영문 머리말 `WEDDING INVITATION`, 이름(안영우 | 정보영), 제목, 사진, 일시와 장소, 아래 화살표.
- 제목은 "일곱 번째 겨울," / "결혼합니다" 두 줄이다. 30px, 줄 높이 42px, 자간 4px, 굵게 하지 않는다.
- 상단 여백은 40px이다. 일시와 장소가 첫 화면 안에 보여야 한다.
- 사진: `IMG_2323.jpg`(3:4). `aspect-ratio: 3 / 4; height: min(440px, 52vh); max-width: 100%`. 원본(3024×4032px, 18MB)은 긴 변 1600px로 줄여 `public/images/cover.jpg`에 둔다.
- 일시와 장소는 세 줄이다: `2026. 12. 05. SAT`, "토요일 오후 2시 20분", "경기교총웨딩하우스 단독홀".
- 모션은 1.2초 안에 끝난다: 사진 0초, 머리말과 이름 0.2~0.4초, 글자별 모션 0.5초 시작, 일시 0.6초.
- 접근성: `h1`에 `aria-label`, 글자별 `span`은 `aria-hidden`. `prefers-reduced-motion`에서는 모션을 끈다.

### S-02 모시는 글, S-02-1 연락하기 시트

- 머리말 `INVITATION`, 제목 "소중한 분들을 초대합니다".
- 인사말은 실물 청첩장의 세 문단이다.
- 혼주 소개는 "안기원 · 김윤정 의 장남 **영우**" 형식의 두 줄이다.
- "연락하기" 버튼은 아래에서 올라오는 시트를 연다.
- 시트: 신랑측(신랑, 아버지, 어머니)과 신부측(신부, 아버지, 어머니). 사람마다 전화(`tel:`)와 문자(`sms:`) 아이콘 버튼.
- 번호가 없는 사람은 행을 숨긴다. 한쪽의 번호가 모두 없으면 "신랑측" 또는 "신부측" 라벨도 숨긴다.

### S-03 예식 일시

- 머리말 `WEDDING DAY`, 제목 "예식 일시". 날짜 `2026. 12. 05`, "토요일 오후 2시 20분", "경기교총웨딩하우스 단독홀".
- 달력은 카드 없이 위아래 1px 선으로 구분한다. 5일에 블루 하트와 흰 숫자.
- 카운트다운 라벨은 "일 / 시간 / 분 / 초"다. 서버 렌더링 시점에는 숫자 자리에 "--"를 둔다.
- "N일 남았습니다"는 한국 시간 기준의 달력 날짜 차이로 계산한다. 타이머 값을 쓰지 않는다.

| 시점 | 타이머 | 문구 |
| --- | --- | --- |
| 예식 전날까지 | 보임 | 영우 ♥ 보영의 결혼식이 N일 남았습니다 |
| 당일, 예식 전 | 보임 | 오늘은 영우 ♥ 보영의 결혼식 날입니다 |
| 당일, 예식 후 | 숨김 | 오늘은 영우 ♥ 보영의 결혼식 날입니다 |
| 다음 날부터 | 숨김 | 영우 ♥ 보영의 결혼식에 함께해 주셔서 감사합니다 (서비스를 내리기 전까지만 보인다) |

### S-04 오시는 길

- 머리말 `LOCATION`, 제목 "오시는 길". 장소명(굵게), 주소(15px)와 그 오른쪽의 "복사" 버튼(아이콘과 글자).
- 지도: 카카오맵. 잠긴 상태로 시작하고 "지도 움직이기"로 잠금을 푼다. 다시 잠글 수 있다. 하트 핀과 장소명.
- 지도를 불러오는 중과 불러오지 못했을 때는 지도 자리에 안내 문구를 보여준다. 아래의 링크와 교통 안내는 항상 보인다.
- 지도 앱 링크: 네이버지도, 카카오맵, 티맵. 이름 왼쪽에 각 앱의 공식 아이콘(시안은 임시 표시).
- 교통 안내(15px): 블루 항목명과 1px 구분선. 주차, 지하철, 셔틀버스, 마을버스, 간선버스.

### S-05 갤러리

- 머리말 `GALLERY`, 제목 "갤러리". 대표 사진 1장(2×2칸)과 작은 사진 5장, "사진 더 보기" 보조 버튼.
- 확대 보기는 `<dialog>`다. 닫기, 이전과 다음, 순번 표시가 있다.
- 더 본 뒤에는 접을 수 있다. 첫 화면 사진 외에는 지연 로딩한다.

### S-06 안내사항

- 머리말 `INFORMATION`, 제목 "안내사항". 현재 항목은 포토부스 하나다.
- 구성: 흰 원 안의 포토부스 선 아이콘(인라인 SVG), 소제목 "포토부스 이용안내", 네 줄 문구.
- 문구: "예식 당일, 포토부스가 준비됩니다. / 환한 미소를 사진으로 남기시고 / 포토부스 화면에 방명록을 적어 주시면 / 소중히 간직하겠습니다."
- 포토부스가 있다는 사실만 알린다. 위치와 운영 시간은 적지 않는다.
- 포토부스 방명록은 예식장 현장의 기기다. 이 페이지의 축하 메시지와 별개이므로 두 섹션을 연결하지 않는다.
- 항목은 `wedding.ts`의 배열이다. 항목이 하나일 때는 캐러셀을 쓰지 않는다.

### S-07 마음 전하실 곳

- 머리말 `ACCOUNT`, 제목 "마음 전하실 곳", 세 줄 안내 문구.
- 신랑측과 신부측을 모두 펼친 상태로 시작한다. 접기와 펼치기는 서로 독립적이다(`<details open>` 두 개).
- 행: 관계와 이름, 은행명과 계좌번호(17px, `user-select: all`), "복사" 버튼. 복사되는 문자열은 "은행명 계좌번호"다. 행은 고정 높이가 아니라 `min-height: 72px`다.

### S-08 축하 메시지, S-08-1 작성 시트

- 머리말 `GUESTBOOK`, 제목 "축하 메시지", 안내 문구.
- "축하 메시지 남기기" 기본 버튼은 목록 위에 둔다.
- 메시지는 최근 5개를 보여주고 "이전 메시지 더 보기" 보조 버튼으로 5개씩 더 불러온다.
- 카드: 이름, 날짜, 글자 버튼 "삭제", 메시지.
- 작성 시트: 이름(20자), 비밀번호(숫자 4자리, 삭제할 때 필요), 메시지(200자, 글자 수 표시), "등록하기".
- 끝맺음 문구나 날짜는 두지 않는다.

### S-09 공유하기

- 머리말 `SHARE`, 제목 "청첩장 공유하기". 같은 크기의 사각 버튼 두 개: "카카오톡 공유하기", "링크주소 복사하기".
- 카카오톡 아이콘은 공식 아이콘으로 교체한다(시안은 일반 말풍선).
- SDK를 불러오지 못하면 카카오톡 버튼을 숨기고 링크 복사만 남긴다.
- 그 아래에 "개발자 버전으로 보기" 링크를 둔다(시안에는 아직 없다).
- 공유 미리보기를 위해 Open Graph 제목, 설명, 1200×630 이미지를 설정한다.

## 5. 공용 동작

### 복사와 토스트

- 토스트는 페이지에 하나다. `position: fixed; bottom: calc(24px + env(safe-area-inset-bottom))`, 화면 하단 중앙, `role="status"`.
- 성공: 토스트("계좌번호를 복사했습니다" 등)와 함께 누른 버튼의 글자가 2초 동안 "복사됨"으로 바뀐다.
- 실패: "복사하지 못했습니다. 계좌번호를 길게 눌러 복사해 주세요".
- 계좌, 주소, 링크 복사가 같은 토스트를 쓴다.

### 시트

- 네이티브 `<dialog>`다. 내용 높이만큼만 아래에서 올라온다(`max-height: 85dvh; overflow-y: auto`). 화면 전체를 덮지 않는다.
- 위쪽의 어두운 바탕을 누르면 닫힌다. 오른쪽 위의 X로도 닫힌다. 손잡이 막대는 두지 않는다.
- 닫으면 포커스가 시트를 연 버튼으로 돌아온다.

### 시안에 그리지 않은 상태

| 영역 | 구현할 때 처리할 상태 |
| --- | --- |
| 방명록 목록 | DB 조회에 실패했을 때의 안내 문구(나머지 페이지는 정상), 0개일 때의 빈 상태, 불러오는 중과 더 없을 때의 "더 보기", 긴 이름의 말줄임 |
| 메시지 등록 | 필드별 검증 오류, 제출 중, 실패(입력 유지, 시트 안에 오류 문구), 성공(시트를 닫고 목록 맨 위에 추가) |
| 메시지 삭제 | 비밀번호 입력, 틀렸을 때의 문구, 삭제 확인, 연속 실패 제한. 부적절한 메시지는 Supabase 관리 화면에서 직접 지운다 |
| 작성 시트 | 입력 중에 바탕을 눌렀을 때 입력값을 유지할지, iOS 키보드가 "등록하기"를 가리는지 |
| 지도 | 불러오는 중, 실패, 다시 잠그기, 티맵 앱이 없는 기기의 링크 동작 |
| 갤러리 | 확대 보기의 조작, 접기, 사진 로딩 실패 |
| 안드로이드 뒤로 가기 | 시트가 열린 상태에서 누르면 시트만 닫히는지 |
| 예식 당일 | 카운트다운(S-03의 표). 예식이 끝나면 서비스를 내리므로 그 이후의 상태는 만들지 않는다 |

## 6. 개발자 테마 (D-2 코드 에디터)

### 원칙

- 섹션마다 위에는 실제 구현과 같은 구조의 코드 조각, 아래 PREVIEW에는 일반 문장과 일반 버튼을 둔다. 개발 용어를 몰라도 일시, 장소, 지도, 계좌, 연락처를 읽을 수 있어야 한다.
- 문구, 섹션 순서, 공용 동작, 상태 처리는 일반 테마와 같다.
- 사진은 3:4 비율을 유지한 채 240×320px로 보여준다.

| 값 | 용도 |
| --- | --- |
| `#1E2030` | 배경 |
