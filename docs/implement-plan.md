## 공통 원칙

- 한 단계는 브랜치 하나, PR 하나 크기로 끝낸다. 브랜치는 항상 `main`에서 분기하고, 이름은 `<type>/<두 자리 단계 번호>-<주제>` 형식으로 짓는다(예: `feat/01-foundation`, `chore/10-final-check`). 단계를 마칠 때마다 `pnpm lint`와 `pnpm build`를 통과시키고 `main`에 병합한 뒤, 프로덕션 주소를 실제 휴대폰에서 연다.
- 통합 브랜치는 두지 않는다. 혼자 작업하고, 실물 청첩장을 나누어 주기 전에는 프로덕션 주소로 들어오는 하객이 없으므로 `main`에서 바로 확인한다. 카카오 SDK는 등록된 도메인에서만 동작하는데, 프로덕션 도메인은 어차피 등록하므로 지도와 공유도 `main`에서 확인한다.
- 실물 청첩장을 나누어 준 뒤에는 `main`에 병합한 내용이 하객에게 바로 보인다. 출시 뒤에 하는 단계(8단계, 12~17단계)는 PR의 프리뷰 배포에서 먼저 확인하고 병합한다. 프리뷰 주소에서는 카카오 지도와 공유가 동작하지 않는다. 프리뷰 주소에 접근 보호(Deployment Protection)가 켜져 있으면 휴대폰에서 열 때 Vercel 로그인을 요구하므로, 프리뷰를 처음 쓸 때 설정을 확인한다.
- git commit과 git push는 사용자가 지시했을 때만 한다.
- 내용은 `src/config/wedding.ts`에서만 가져온다. 섹션 컴포넌트에 문구를 직접 적지 않는다.
- 로직과 모양을 분리한다. 날짜 계산, 복사, 카운트다운, 지도 로딩, 방명록 Server Actions는 `src/lib/`과 `src/db/`에 두고, 모양은 테마별 컴포넌트가 맡는다. 이렇게 해야 개발자 테마에서 로직을 다시 만들지 않는다.
- 새 의존성은 8단계에서 `@supabase/supabase-js` 하나만 추가한다. 문법 강조, 애니메이션, 모달, 캐러셀, 폼 검증 라이브러리는 쓰지 않는다.

## 일반 테마 (1~11단계, 시안 S-01~S-09)

**1단계. 기반**
- `globals.css`에 `design-plan.md`의 토큰 표의 값과 종이 질감 배경을 정의한다. 질감은 이미지 파일 없이 SVG 노이즈 필터(240px 반복)로 그린다.
- `layout.tsx`에 서체 세 개(`next/font/google`), 448px 중앙 컨테이너, 뷰포트, 기본 메타데이터를 둔다.
- `wedding.ts`에 타입과 내용을 입력한다: 이름, 혼주, 일시(ISO, +09:00), 장소, 인사말, 교통 안내, 안내사항 배열, 계좌, 연락처, 사진 목록, 좌표와 지도 링크.
- `ui/`의 정적 조각(`SectionHeader`, `Button`, `Card`)을 만들고 테스트 페이지를 지운다.
- 완료 기준: 빈 섹션 머리말 아홉 개가 종이 배경 위에 보인다. 360px과 390px 폭에서 가로 스크롤이 없다. 한글 서체가 자체 호스팅되는지 확인했다.

**2단계. 첫 화면과 모시는 글 (S-01, S-02)**
- `Cover`: 사진(`priority`, `aspect-ratio: 3 / 4; height: min(440px, 52vh)`), 두 줄 제목, 글자 모션(CSS), `aria-label`, `prefers-reduced-motion`.
- `Greeting`: 인사말, 혼주 한 줄 소개. 연락하기 버튼은 4단계에서 시트와 연결한다.
- 완료 기준: 실제 휴대폰의 첫 화면에서 일시와 장소가 스크롤 없이 보인다. 모션이 1.2초 안에 끝난다.

**3단계. 예식 일시 (S-03)**
- `lib/date.ts`에 한국 시간 기준의 날짜 차이 함수와 남은 시간 함수를 순수 함수로 만든다. 예식 전날 오후, 당일 예식 전, 당일 예식 후, 다음 날의 네 경우를 `node --test`로 검증한다(Node 22에서 TypeScript 파일을 바로 실행할 수 있는지 먼저 확인하고, 안 되면 검증 스크립트를 `.mjs`로 둔다).
- 달력은 서버 컴포넌트로 그리고, 카운트다운만 클라이언트 컴포넌트로 둔다. 서버 렌더링 시점에는 숫자 자리에 "--"를 둔다.
- 완료 기준: 네 경우의 문구가 맞다. 하이드레이션 경고가 없다.

**4단계. 공용 상호작용 조각과 연락하기 시트 (S-02-1)**
- `Toast`: 페이지에 하나만 두고 화면 하단에 고정한다. `role="status"`.
- `lib/clipboard.ts`와 `CopyButton`: 성공하면 토스트와 "복사됨" 2초, 실패하면 안내 문구.
- `Sheet`: 네이티브 `<dialog>` 래퍼. 아래에서 올라오고 `max-height: 85dvh`, 바탕을 누르면 닫히며, 닫을 때 포커스가 연 버튼으로 돌아온다.
- 연락하기 시트를 `Greeting`에 연결한다(`tel:`, `sms:`).
- 완료 기준: 카카오톡 인앱 브라우저, iOS Safari, 삼성 인터넷에서 복사와 시트가 동작한다. 안드로이드의 뒤로 가기로 시트만 닫히는지 확인했다.

**5단계. 마음 전하실 곳과 안내사항 (S-07, S-06)**
- `Accounts`: `<details open>` 두 개, 계좌번호 17px와 `user-select: all`, `CopyButton`. 복사되는 문자열은 "은행명 계좌번호"다(예: "○○은행 000-0000-0000"). `wedding.ts`에는 은행명과 계좌번호를 따로 저장하고, 복사할 때 합친다.
- `Info`: 포토부스 아이콘(인라인 SVG)과 안내 문구. `wedding.ts`의 배열을 반복한다.

**6단계. 오시는 길 (S-04)**
- `lib/kakao.ts`: SDK 스크립트를 한 번만 불러오는 로더. `IntersectionObserver`로 지도 영역이 가까워졌을 때 불러온다. 동적 로딩 방법(`autoload=false`)은 이 단계에서 공식 문서로 확인한다.
- `KakaoMap`(클라이언트): 잠긴 상태로 시작, "지도 움직이기"와 다시 잠그기, 하트 핀, 불러오는 중과 실패 문구.
- 지도 앱 링크 세 개(공식 아이콘으로 교체), 주소 복사, 교통 안내 15px.
- 완료 기준: 키가 없거나 SDK가 실패해도 링크와 교통 안내는 보인다. 페이지를 스크롤할 때 지도가 스크롤을 가로채지 않는다.

**7단계. 갤러리 (S-05)**
- 사진을 긴 변 1600px로 줄여 `public/images/gallery/`에 둔다. `next/image`의 `sizes`를 지정하고 지연 로딩한다.
- 더 보기와 접기, `<dialog>` 확대 보기(닫기, 이전과 다음은 CSS scroll-snap, 순번 표시).
- 완료 기준: 첫 화면의 LCP에 갤러리 사진이 끼어들지 않는다.

**8단계. 축하 메시지 (S-08, S-08-1)**
- DB는 Supabase(Postgres)이고, `supabase-js`를 서버에서만 쓴다. 추가하는 의존성은 `@supabase/supabase-js` 하나다. HTTP로 통신하므로 서버리스에서 DB 연결 수를 관리하지 않아도 된다. Drizzle 같은 ORM과 마이그레이션 도구는 쓰지 않는다.
- `src/db/client.ts`는 `server-only`로 표시하고, 환경 변수 `SUPABASE_URL`과 `SUPABASE_SERVICE_ROLE_KEY`로 클라이언트를 만든다. 쿼리 함수(목록, 등록, 삭제)는 `src/db/guestbook.ts`에 둔다.
- 테이블: `guestbook(id, name, message, password_hash, created_at, deleted_at)`. 만드는 SQL은 `src/db/schema.sql`에 보관한다.
- 보안: 테이블에 RLS를 켜고 정책은 만들지 않는다. 자동으로 열리는 REST API에서 공개 키로는 아무것도 읽지 못하게 하기 위해서다. 조회와 쓰기는 Server Actions에서만 하고, `service_role` 키는 `NEXT_PUBLIC_` 접두사 없이 서버 환경 변수로만 둔다. 브라우저에 Supabase 클라이언트를 두지 않는다.
- Server Actions: 등록, 삭제, 5개씩 더 보기. 입력값은 서버에서 직접 검증한다(이름 1~20자, 메시지 1~200자, 비밀번호 숫자 4자리). 비밀번호는 `node:crypto`의 scrypt로 해시한다. 숨은 필드로 봇을 거르고, 같은 IP의 연속 등록과 삭제 실패를 제한한다.
- 상태: 빈 목록, 제출 중, 검증 오류, 실패(입력 유지), 성공(시트를 닫고 목록 맨 위에 추가), 삭제 확인과 비밀번호 오류.
- 부적절한 메시지는 Supabase 관리 화면의 테이블 편집기에서 직접 지운다. 관리자용 화면이나 관리자 비밀번호는 만들지 않는다.
- 일시 중지 방지: 무료 요금제는 최근 7일의 DB 활동이 적으면 프로젝트를 일시 중지한다. 외부 서비스 cron-job.org(https://console.cron-job.org/jobs)에서 주기적으로 호출하여 막는다. 예약 실행은 사용자가 cron-job.org에서 직접 설정하며, 저장소에는 크론 설정(`vercel.json`의 `crons` 등)을 두지 않는다.
  - 저장소에는 호출을 받는 주소 하나만 둔다: 라우트 핸들러 `app/api/keep-alive/route.ts`. 페이지(`/`)를 호출하는 것으로는 부족하다. 페이지는 정적으로 만들어 두고 방명록을 쓸 때만 다시 만들기 때문에, 페이지 요청은 DB까지 가지 않는다.
  - 핸들러는 캐시하지 않도록 하고 방명록 테이블을 가볍게 조회한 뒤(행 수 조회 정도) 200을 돌려준다. 조회에 실패하면 500을 돌려주어 cron-job.org의 실패 알림으로 일시 중지를 알 수 있게 한다.
  - 핸들러는 `Authorization` 헤더를 환경 변수 `KEEP_ALIVE_SECRET`과 비교하고, 다르면 401을 돌려준다. 비밀 값은 주소의 쿼리에 넣지 않는다(로그에 남는다). cron-job.org에서 요청 헤더를 지정할 수 있는지는 설정할 때 확인한다.
  - 호출 주기는 하루 네 번 정도로 한다. Supabase 문서가 "하루에 몇 건의 요청"을 기준으로 적고 있기 때문이다.
  - AGENTS.md의 "API 라우트를 따로 만들지 않는다"는 방명록 쓰기와 삭제에 대한 규칙이다. 이 핸들러는 일시 중지 방지 전용 예외다.
  - 호출과 별개로, 방명록 조회가 실패해도 나머지 페이지는 정상으로 보이고 방명록 자리에는 안내 문구만 나오게 한다.
- 완료 기준: 프리뷰 환경에서 등록과 삭제가 되고, 잘못된 입력이 서버에서 거부된다. 공개 키로 REST API를 호출했을 때 행이 읽히지 않는다. `/api/keep-alive`를 `KEEP_ALIVE_SECRET` 없이 호출하면 401이 나온다.

**9단계. 공유하기와 미리보기 (S-09)**
- 카카오 JavaScript SDK의 공유 기능(호출 방법은 이 단계에서 공식 문서로 확인), 링크주소 복사.
- `metadataBase`(`NEXT_PUBLIC_SITE_URL`), Open Graph 제목과 설명, 1200×630 이미지.
- 페이지 맨 아래에 "개발자 버전으로 보기" 링크 자리를 둔다(개발자 테마 단계가 끝나면 켠다).
- 완료 기준: 카카오톡 대화방에 링크를 붙였을 때 미리보기가 나온다.

**10단계. 마감 점검**
- `design-plan.md`의 "시안에 그리지 않은 상태" 표를 하나씩 확인한다.
- 접근성: 키보드 이동, 스크린 리더의 제목 구조, 대비, `prefers-reduced-motion`.
- 실제 기기: 아이폰 Safari, 갤럭시 삼성 인터넷과 크롬, 카카오톡 인앱 브라우저. 360px 폭.
- 성능: 첫 화면 사진의 LCP, 서체 로딩, 지도 SDK가 첫 로딩에 포함되지 않는지.
- 예식 당일의 표시(카운트다운 문구와 타이머 숨김)를 확인한다. 예식이 끝나면 서비스를 내리므로 그 이후의 상태는 점검하지 않는다.
- 검색 엔진 차단: noindex 메타, `robots.txt`, `X-Robots-Tag`.

**11단계. 출시**
- 프로덕션 환경 변수와 Kakao Developers의 운영 도메인 등록을 확인한다. Supabase 프로젝트가 일시 중지되지 않았는지 확인한다.
- 1~7단계, 9~10단계가 모두 `main`에 병합되어 있는지 확인한다.
- 실물 청첩장의 QR 코드로 실제 접속해 본다.

## 기술 메모

### 카카오 SDK

공식 문서(https://apis.map.kakao.com/web/guide/, https://apis.map.kakao.com/web/documentation/)에서 확인한 내용이다.

- Kakao Developers에서 앱을 만들고 JavaScript 키를 발급받는다. JavaScript SDK 도메인을 등록해야 지도가 표시된다.
- 스크립트 주소는 `//dapi.kakao.com/v2/maps/sdk.js?appkey=<JavaScript 키>` 형식이다.
- 지도를 담는 요소에는 너비와 높이가 반드시 지정되어 있어야 한다.
- `kakao.maps.Map`에 `setDraggable`, `setZoomable` 메서드가 있다.

아직 확인하지 못했고, 해당 단계에서 공식 문서로 확인한다.

- 동적 로딩을 위한 `autoload=false`와 `kakao.maps.load()` 사용법 (6단계)
- 마커와 커스텀 오버레이 API, 무료 호출 한도 (6단계)
- 카카오톡 공유의 호출 방법과 메시지 템플릿 (9단계)

정한 방침은 다음과 같다.

- 앱 키는 `NEXT_PUBLIC_KAKAO_MAP_APP_KEY`다. 브라우저에 노출되는 값이므로 보호 수단은 도메인 등록이다. 지도와 공유가 같은 키를 쓴다.
- 등록할 도메인: `https://wedding.ywtechit.com`, `http://localhost:3000`.

### 확인한 환경

- `next/font/google` 목록에 고운돋움(400), Bona Nova(400, 700), Noto Sans KR, JetBrains Mono, 나눔고딕코딩(400, 700)이 있다. 한글 글리프가 빌드 결과에 자체 호스팅되는지는 1단계에서 확인한다.
- 로컬 Node는 v22.23.1이고, CI는 Node 22에서 `pnpm lint`와 `pnpm build`를 실행한다.
- `main`에는 연결 테스트 페이지가 올라가 있다.

### 라우트 구조

- 라우트 그룹으로 루트 레이아웃을 나눈다: `app/(main)/layout.tsx`, `app/dev/layout.tsx`.
- `src/config/wedding.ts`, `src/lib/`, `src/db/`는 두 테마가 공유한다. 모양은 `components/sections/`와 `components/dev/`로 나눈다.
